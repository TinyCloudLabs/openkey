`POST /api/delegate` hosts the TinyCloud space the client asked for before it responds, when approving creates a missing canonical space (managed key, Auto-Sign on). Inside the setup's existing lock, the managed key signs the same host SIWE the setup already signed (peer id, then `tinycloud.space/host` on that one space) and submits it. `spaceReady: true` is returned only when the node's response to that host delegation lists the space under `activated`; a 2xx without it is reported as `tinycloud_bootstrap_space_not_hosted`. The other five spaces and the seeding still run in the background, in the same run, and skip the space that is already hosted. No new ability is signed.

If the space is not hosted within `TINYCLOUD_BOOTSTRAP_REQUESTED_SPACE_TIMEOUT_MS` (default 10000 ms, capped at 60000), the response is `spaceReady: null`, `spacePending: true` and `spaceError: "tinycloud_requested_space_timeout"` (clients that wait on `spacePending` with `spaceReady: null` keep waiting), and the setup continues in the background. A failure that a background retry will try again (see below) is reported the same way, `spaceReady: null` + `spacePending: true`, with the failure in `spaceError`. A failure no retry will follow (a non-retryable code, or retries turned off) keeps the existing `spaceReady: false` and `spaceError`. `TINYCLOUD_BOOTSTRAP_SYNC_BUDGET_MS` now applies only to `/api/keys/:id/sign`.

Every request the setup makes to the TinyCloud node now has a timeout (`TINYCLOUD_BOOTSTRAP_NODE_TIMEOUT_MS`, default 15000 ms, for the peer id, host and activation requests; `TINYCLOUD_BOOTSTRAP_NODE_INVOKE_TIMEOUT_MS`, default 30000 ms, for the schema, seeding and encryption-network requests; both capped at 60000), so a hung call fails the run and releases its lock instead of holding it through the heartbeat. A timeout is recorded under `tinycloud_bootstrap_node_timeout`. The approval routes' own session activation (`/api/delegate`, `/api/delegate/complete`) uses the same 15 s bound; a timeout is reported as `hostActivated: false`.

A failed setup started by an approval is retried in the background without another approval: three retries after 5 s, 15 s and 45 s (`TINYCLOUD_BOOTSTRAP_RETRY_DELAYS_MS`: comma-separated milliseconds, or `off`). Each retry unseals the managed key again instead of holding it while it waits. A failed state keeps its `failureCode` and `failureReason` while it is retried; a successful run clears them.

`tinycloud_bootstrap_background_failed` and `tinycloud_bootstrap_background_completed` now carry `duration_ms` and `attempt`, and, for approvals, `requested_space_hosted` (`yes`, `no` or `timeout`: whether the requested space was hosted before the response). New error codes: `tinycloud_bootstrap_node_timeout`, `tinycloud_bootstrap_space_not_hosted` (TC-1608).
