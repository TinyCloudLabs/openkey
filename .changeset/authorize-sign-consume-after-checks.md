`/api/delegate/authorize-sign` checks context bindings, preview approval, selection, narrowing, regenerated SIWE, and external signatures before atomically consuming its single-use authorization context and preview approval together. Refused requests leave both tokens usable for a corrected retry; of concurrent sign attempts only one can sign, and replays are refused. Managed signing failures after consumption still require a fresh approval.

An empty selection with required capabilities still returns `required-action-missing`, and unknown action IDs still return `action-not-in-baseline`. When the caller has keys, `/authorize-sign` now rejects another account's context with `400 user_mismatch` (matching `/authorize-sign-preview`) before inspecting the selection or spending the owner's context. Previously, unrelated keys yielded `404 key_not_found`; a case-variant record for the same wallet yielded `400 user-mismatch` and spent the owner's context. A caller with no keys still receives `404 key_not_found`. An expired context returns `context-expired` on `/authorize-sign`, `/authorize-sign-preview`, the managed approval, and versioned `/complete` only while its record remains stored; issuing a new context prunes expired records, after which it returns `context-not-found`. Likewise, an expired preview approval returns `preview-approval-expired` on `/authorize-sign` until a new preview approval prunes it, after which it returns `preview-approval-not-found`. A context expiring between check and consume cannot sign and remains stored until the next prune.
