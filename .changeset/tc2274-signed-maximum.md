A signed CLI approval request and a device request can now carry a suggested default beside the longest lifetime they sign. The signed request takes an optional `suggestedLifetimeSeconds` (from `@tinycloud/share-envelope` 1.4.1), the device start body an optional `suggestedTtlSeconds` (60 s up to `delegationTtlSeconds`, else 400 `invalid_request`). The approval screen shows "Approval expires: <suggested> (Change)" and the owner can pick anything up to the signed maximum; the device page selects the suggestion first. The 30-day cap is lifted for these two paths because the requester signs the maximum: `delegationTtlSeconds` is any whole number of seconds from 60 up to what a SIWE date can hold, and a signed request's `grantLifetimeSeconds` is no longer clamped to 30 days at `/prepare` (a link's own `expiry` still is). `/api/delegate/authorize-sign-preview` now refuses a chosen expiry unless the app opted in (`expiryChangeable: true`, bound at `/authorize-sign-prepare`; error `expiry_not_changeable`), refuses one later than the CLI asked for on a prepared handoff, and `/authorize-sign` reads the sealed preview's expiry only for that preview's own user and context. UI: the long-value limit note shows once, the access-end line ("This access lasts until …") follows a pick before approval, and the link notice drops its own "Expires" row where the picker line shows it. Details: TC-2274
