TC-2356: `GET /api/internal/metrics` (same `INTERNAL_METRICS_TOKEN` gate) adds a counts-only `users` block: `{ total, buckets, real, realActive: { d1, d7, d30 }, realNew7d, apps }`. Each account lands in exactly one bucket, checked in this order: `team_by_wallet` (wallets in `SCOREBOARD_EXCLUDE_ADDRESSES`, compared lowercase and mapped through `ethereum_keys.address`, so every key of that person), `internal_team_domain`, `disposable_mail_domain` (built-in disposable providers plus `SCOREBOARD_DISPOSABLE_DOMAINS`, so a rotating provider such as mail.tm can be added without a code deploy), `internal_agent_or_qa`, `test_or_throwaway_domain` (example/test/invalid/localhost), `plus_addressed`, `test_like_name`, `never_completed_signup`, `explicit_exclusions` (user ids in `SCOREBOARD_EXCLUDE_USER_IDS`), `bot_like` (50 or more sessions created on one UTC day in the last 30 days). `real` is everyone else; `realActive` counts real accounts by last session update. `apps` lists, per OAuth client display name, the distinct real accounts that received an access token in the last 7 and 30 days. The response carries no emails, addresses, ids or per-user data. If the users query fails, `users` is `null` and the existing counts are unchanged. New env vars `SCOREBOARD_EXCLUDE_ADDRESSES` and `SCOREBOARD_DISPOSABLE_DOMAINS` (both passed through `docker-compose.prod.yml`).
