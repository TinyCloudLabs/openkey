TC-476 · Console host journey

OpenKey Account and Console are distinct, continuous surfaces.

The account app remains the place for personal keys and identity. The console is the administrative control plane for an organization.

Happy path

1
OpenKey Account
https://openkey.so/dashboard exposes a clearly labeled Admin console destination.
2
OpenKey Console
https://console.openkey.so/console lists and creates organizations.
3
Tenant workspace
/console/:organizationId/apps keeps the organization, role, and administrative navigation visible while work happens.

Visual verification

The account dashboard keeps the administrative destination explicit and visually distinct. This is a browser capture of the built worker with the dashboard's API responses represented by a signed-in fixture.

Authentication continuity

A signed-out console visitor is sent to the account sign-in screen with the exact console destination as a constrained return URL. After account sign-in, the shared .openkey.so session cookie returns the visitor to that console route. Only the configured console origin and the /console path family are accepted as cross-origin return targets.

Host boundary

openkey.so/console/:organizationId/apps?tab=active responds with a permanent redirect to console.openkey.so/console/:organizationId/apps?tab=active. The bare console hostname redirects to /console. Legacy console-host dashboard bookmarks return to the account host, while unrelated personal paths remain a 404 rather than rendering the personal account app.

Local development

With no VITE_CONSOLE_ORIGIN, account and console links stay on the same local Vite host. Contributors can prove the journey at http://localhost:5173/console without local DNS. Production supplies VITE_CONSOLE_ORIGIN=https://console.openkey.so, CONSOLE_ORIGIN=https://console.openkey.so, and includes the console origin in API CORS.
